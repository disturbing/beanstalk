## 1. Track A — GitHub auth today and where it hurts agents

| Mechanism | Facts (sourced) | Agent pain |
|---|---|---|
| GitHub App installation token | Expires after 1 hour; `permissions` and `repositories` (≤500) can narrow a token below the app grant. [docs](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app). Rate: min 5,000/h, +50/h per repo and per user beyond 20, cap 12,500/h (15,000 Enterprise). [docs](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) | JWT→exchange dance; token dies mid-task; one installation covers every granted repo, which is exactly the blast radius Invariant exploited. Fleets of agentic workflows exhaust the shared installation quota in bursts. [gh-aw #29318](https://github.com/github/gh-aw/issues/29318) |

The "not a member" gap kills fork-and-PR flows. Long-lived bearer sitting in an agent's env is the Comment-and-Control payoff. |

[GitHub blog, 2025-11-25](https://github.blog/ai-and-ml/github-copilot/how-githubs-agentic-security-principles-make-our-ai-agents-as-secure-as-possible/). ## 2. Track B — Identity models worth copying

- **SPIFFE/SPIRE**: `spiffe://trust-domain/path` identities, short-lived X.509-SVID/JWT-SVIDs rotated via the Workload API after node/workload attestation. [spiffe.io](https://spiffe.io/docs/latest/spiffe-about/overview/) Lesson: identity is per workload, short-lived, attested — not a pasted secret.
- **GitHub Actions OIDC**: per-job token with `sub`, `repository`, `ref`, `actor`, `job_workflow_ref`, `environment`, `run_id`; cloud trusts a subject pattern. [docs](https://docs.github.com/en/actions/concepts/security/openid-connect) Lesson: the token carries *what context* is acting, so policy can key on branch/task.
- **Workload Authorization Grant (Anthropic/OpenAI/Okta/Defakto/Ping)**: "Each workload is identified by an opaque identifier that is never reassigned"; the platform signs an RFC 7523 JWT grant; the AS "does not reject a workload because it has not seen it before". [draft-carleton-workload-authz-grant-01](https://datatracker.ietf.org/doc/html/draft-carleton-workload-authz-grant-01). Motivation per Anthropic's Oktane talk: a shared-space agent "belongs to nobody, so it has no identity to borrow". [Doering](https://andrewdoering.org/blog/2026/anthropic-workload-authorization-grant/). Companion drafts: Agent Delegation Chain (monotonic attenuation, DPoP binding, status-list revocation) [AI Stack Current](https://aistackcurrent.com/protocols/agent-delegation-chain/); on-behalf-of via RFC 8693 token exchange. [Oleria](https://www.oleria.com/blog/on-behalf-of-identity-at-machine-speed)
- **Capability tokens**: Biscuit = public-key verification, offline attenuation, Datalog policy in or beside the token, per-token revocation ids that also revoke descendants; implementations in Rust, Go, JS/WASM, Python, C#. [biscuitsec.org](https://www.biscuitsec.org/). Macaroons = HMAC-chained caveats incl. third-party discharges. [Hivebook](https://hivebook.wiki/wiki/macaroons-bearer-tokens-with-contextual-caveats). UCAN 1.0 = DID principals, "each direct delegation MUST either directly restate or attenuate", delegation chain "is by definition a provenance log", separate invocation and revocation specs. [ucan-wg/spec](https://github.com/ucan-wg/spec). These fit "agent forks repo, gets a token only for that fork, can open PR but not merge" exactly: the fork token is an attenuation of the user's grant.
- **OAuth brokers**: Composio/Arcade/Nango keep per-user connected accounts so "the model never sees the OAuth exchange"; Nango Agent Sessions grant temporary access to selected accounts and tools. [Nango](https://nango.dev/blog/how-to-give-ai-agents-access-to-user-accounts-without-exposing-oauth-tokens/), [comparison](https://dreaming.press/posts/2026-06-23-composio-vs-arcade-vs-toolhouse.html)
- **Cloudflare primitives**: `@cloudflare/workers-oauth-provider` 0.4.0 (Mar 2026) does OAuth 2.1 + PKCE, stores only hashes in KV, supports Client ID Metadata Documents, and wraps a Worker so handlers receive the authenticated props. [npm](https://registry.npmjs.org/%40cloudflare%2Fworkers-oauth-provider), [repo](https://github.com/cloudflare/workers-oauth-provider/). Agents SDK docs cover self-hosted, third-party and BYO auth and recommend conditional tool registration so "the LLM never sees tools the user cannot access". [docs](https://developers.cloudflare.com/agents/model-context-protocol/authorization/). Cloudflare Access: service tokens via `CF-Access-Client-Id/Secret` with a Service Auth policy, durations up to 8760h [docs](https://developers.cloudflare.com/cloudflare-one/identity/service-tokens/); every authenticated request carries `Cf-Access-Jwt-Assertion` (claims `email`, `aud`, `iss`), keys at `/cdn-cgi/access/certs`, rotated every 6 weeks [docs](https://developers.cloudflare.com/cloudflare-one/identity/authorization-cookie/validating-json/); Workers read identity via `ctx.access.getIdentity()` and Access apps target `worker` or `preview_worker` destinations. [docs](https://developers.cloudflare.com/workers/configuration/cloudflare-access/). MCP server portals accept service tokens for headless agents (2026-06-26). [changelog](https://developers.cloudflare.com/changelog/post/2026-06-26-mcp-portal-service-tokens/)
- **Artifacts tokens (our substrate)**: `createToken(scope "read"|"write", ttl seconds)`, `listTokens`, `revokeToken`; REST `POST .../tokens {repo, scope, ttl}`; format `art_v1_<40hex>?expires=<unix>`; presented as Bearer header or Basic password. [binding](https://developers.cloudflare.com/artifacts/api/workers-binding/), [REST](https://developers.cloudflare.com/artifacts/api/rest-api/), [git protocol](https://developers.cloudflare.com/artifacts/api/git-protocol/). Limits: 1 GB/repo, 32 MB/blob, 2,000 req/10 s per repo and per namespace control plane, 1 TB/account. [limits](https://developers.cloudflare.com/artifacts/platform/limits/). Pricing $0.15/1k ops, $0.50/GB-month. [blog](https://blog.cloudflare.com/artifacts-git-for-agents-beta/)

### Recommended beanstalk identity/token design

- **Principals**: human `user`; `agent_client` (Claude Code, Codex, Cursor, custom — registered via Client ID Metadata Document, no DCR sprawl); `agent_instance` (opaque, never-reassigned id per running agent, in the WAG sense); `task` (the unit of work; maps 1:1 to an Artifacts fork).
- **Layer 1, session token** (what MCP/API calls carry): OAuth 2.1 access token minted by workers-oauth-provider, audience = beanstalk resource (RFC 8707), JWT claims `sub=user`, `azp=agent_client`, `act={instance}`, `task`, `scope`. Lifetime 1h, refresh 24h, refresh rotation per instance so parallel agents never share a refresh family. Scopes are small and progressive: start with `repo:read task:read`; `pr:write`, `preview:write`, `repo:write` are obtained by incremental `WWW-Authenticate scope=` challenges (MCP 2025-11-25 SEP-835), never granted up front.
- **Layer 2, capability token** (what git and preview URLs accept): a Biscuit (JS/WASM verifier runs in a Worker) issued by beanstalk with facts `repo(fork_id)`, `upstream(repo_id)`, `ops(push, open_pr)`, `branch_prefix("task/<id>/")`, `task(id)`, `instance(id)`, `exp`. The agent can attenuate it offline for a sub-agent (e.g. drop `push`, keep `read`), and every attenuation carries the parent revocation id. Our git endpoint (`git.beanstalk.dev/<ns>/<repo>.git`) verifies the Biscuit and only then mints a 15-minute read / 60-minute write Artifacts token server-side and proxies the smart-HTTP request. Agents never hold `art_v1_` tokens or Cloudflare API tokens, mirroring Sandbox 1.0's "credentials and bindings stay in your Worker".
- **Fork-per-task is the authorization boundary**: `repo.fork` creates the Artifacts fork (`readOnly` upstream view), returns the capability. Opening a PR on upstream is a right on the *fork* token; `merge` is never a capability an agent token can carry — it is a human (or policy-engine) action.
- **Expiry**: session 1h; capability ≤60 min write / ≤15 min read, renewable only while the task is open; preview share links 24h; everything revocable by task, instance, client or user (Biscuit revocation ids, plus `revokeToken` on any Artifacts token still live).
- **Federation**: accept WAG JWT grants from agent platforms (Claude Managed Agents, Codex cloud) and OIDC tokens from GitHub Actions for migration flows; accept Cloudflare Access service tokens for in-account bots. Whether Workers Builds/CI SDK emit OIDC-style identity is **UNVERIFIED**.
- **Audit**: every write stores `{user, agent_client, instance, task, token_id, parent_token_id, tool_name}`; commits get trailers `Agent: <client>/<instance>`, `Task: <id>`, `Agent-Logs-Url:` and `Co-authored-by:` the sponsoring human (Copilot's model, plus the Crash Override `Generated-By` convention). [Crash Override](https://crashoverride.com/resources/knowledge-base/code-ownership/attributing-ai-commits-git) Blame and PR views show the agent lane, not the human's face.
- **Rate limits** per instance *and* per task: copy GitHub's shape (hourly primary + 80 writes/min secondary) but return budget in `_meta` of every tool result so agents back off before 429.

### Proposed beanstalk MCP tool list

Annotations: R = `readOnlyHint:true`; W = write, `destructiveHint:false`; D = `destructiveHint:true`; I = `idempotentHint:true`; O = `openWorldHint:true`.

**context**
1. `whoami` (R) — user, agent client, instance, task, scopes, remaining budget.
2. `search` (R) — code/PR/task search across repos this token can read; results carry trust labels.

**repos**
3. `repo_get` (R) — metadata, default branch, protection rules, open task count.
4. `repo_tree` (R) — tree at ref/path, paginated.
5. `repo_read_file` (R) — file at ref; returns `resource_link` when >32 KB.
6. `repo_diff` (R) — compare two refs or a PR; structured hunks.
7. `repo_fork_for_task` (W, I) — create task fork via Artifacts, claim intent, return capability token + git remote.
8. `repo_commit` (W) — multi-file commit to a `task/<id>/` branch of the fork (server-side, no clone needed).

**branches / coordination**
9. `branch_create` (W, I) — branch in fork from upstream ref.
10. `branch_delete` (D) — delete a task branch.
11. `claim_paths` (W, I) — register intent on paths/modules so other agents see it; returns overlaps.
12. `task_list` (R) — who is working on what, with claims, open PRs, preview URLs.
13. `task_handoff` (W) — structured status/handoff note tied to the task.

**pull_requests**
14. `pr_open` (W, I keyed on fork+branch) — open PR to upstream; body carries agent trailers automatically.
15. `pr_get` (R) — diff summary, checks, conflicts vs upstream head, preview URL, review state.
16. `pr_list` (R) — filter by author, task, state, label.
17. `pr_update` (W) — title/body/ready-for-review/labels.
18. `pr_sync` (W) — rebase/merge upstream into the task branch server-side; returns conflict hunks.
19. `pr_merge` (D) — never callable with an agent capability; triggers elicitation to a human and returns a decision id.

**reviews / checks**
20. `review_submit` (W) — inline comments + `comment|request_changes|approve`; agent approvals are flagged non-binding.
21. `review_comments` (R) — thread list with `author_role` (`owner|writer|external|bot`) on every comment.
22. `check_report` (W, I) — post check run result (tests/lint/visual diff) with summary + artifacts link.

**previews**
23. `preview_deploy` (W, I) — deploy PR/branch to a Worker Preview (or sandbox); returns URL, deployment id, short-lived access grant.
24. `preview_get` (R) — status, URL, recent logs/traces summary, DB binding info.
25. `preview_fetch` (R, O) — HTTP request against the preview with server-side injected auth; body truncated to 8k tokens.
26. `preview_snapshot` (R, O) — Browser Rendering screenshot and/or accessibility/markdown snapshot of a path at a viewport; optional pixel diff vs base.
27. `preview_share_link` (W) — mint 24h human link.

**audit**
28. `audit_list` (R) — actions by task/instance/token for the last N hours.

**Resources** (`beanstalk://`): `repo/{ns}/{repo}/tree/{ref}/{path}`, `pr/{id}/diff`, `pr/{id}/comments`, `preview/{id}/logs`, `task/{id}` (subscribable, `list_changed` on new claims). **Prompts**: `review_pr`, `verify_preview` (deploy → snapshot → fetch → check_report), `resolve_conflicts`, `handoff`.

### Preview architecture options for beanstalk

**Option A — Workers-native (default for Workers repos).** Artifacts push event → CI Workflow (`@cloudflare/ci`) runs lint/test in a sandbox → `wrangler preview --name task-<id>` → URL recorded on the PR. Protect every preview URL with Access (`preview_worker` destination) for humans; agents call `preview_fetch`/`preview_snapshot` through beanstalk, which holds a Service Auth token (whether Service Auth policies can be attached to `preview_worker` apps is **UNVERIFIED**; the docs say advanced policies are edited in Zero Trust after creation). DB: D1 per preview via `previews.d1_databases` bound to a per-task database created at deploy time and migrated in CI; DO-backed state is isolated for free. Limits: 500 previews per account on Paid (so recycle by LRU and task close), 100 deployments per preview, one Worker per repo, no D1 fork (clone by export/import is slow; **UNVERIFIED** at scale). [CI SDK](https://developers.cloudflare.com/changelog/post/2026-08-04-build-and-deploy-on-push/)

**Option B — Sandbox-per-PR (any stack).** A beanstalk DO per task starts a Sandbox 1.0 container from a snapshot of the base image, clones the fork with a 15-minute read token, runs the app's dev server, and serves `https://<task>.preview.beanstalk.dev` by routing the hostname to `getTcpPort()`. Auth is ours: Access JWT for humans (`ctx.access`), a 24h `share()` token for links, and server-side injection for agents. Idle sleep after 10 min, resume from snapshot. Fits backends with Postgres/SQLite in-container (Neon branch optional). Limits: needs a wildcard custom domain; container-seconds cost; single-region per DO; cold start 0.6–4 s. [Sandbox lifecycle](https://developers.cloudflare.com/sandbox/concepts/sandboxes/)

**Option C — Hybrid + visual verification.** Front-end on Worker Previews, API/db in a sandbox, and `preview_snapshot` using Browser Rendering `/screenshot` at fixed viewports on base and head to attach a pixel diff to a `check_report`. Paid limits (30 req/s, 200 browsers) cover thousands of snapshots/hour; Free's 10 min/day does not.

Recommendation: A for the demo (zero infra, Cloudflare's own golden path), B behind the same `preview_*` tools for non-Workers repos, C's snapshot/diff as the agent's "did it actually work" primitive.

## 5. Security — prompt-injection-resistant by construction

1. **Capability, not identity, at every write.** Agent tokens are per-task Biscuits attenuated from the human's grant; no token can both read repos the task didn't claim and write anywhere else. This removes the Invariant precondition (one token spanning public + private). [Invariant](https://invariantlabs.ai/blog/mcp-github-vulnerability)
2. **Trust labels on every string we return.** `review_comments`, `pr_get`, `search` tag content with `author_role` and `trusted:false` for external/bot authors and wrap it as data; default toolsets only surface comments from writers (Copilot's rule), with an explicit `include_external:true` that requires `pr:read_external` scope. [GitHub blog](https://github.blog/ai-and-ml/github-copilot/how-githubs-agentic-security-principles-make-our-ai-agents-as-secure-as-possible/)
3. **Toxic-flow gating server-side.** The server tracks per-session flow state: after a tool returned untrusted content, any write that targets a repo/branch outside the task fork, or any `preview_fetch` to a non-preview host, is refused until an elicitation (URL mode) is approved by the human. [elicitation](https://modelcontextprotocol.io/specification/2025-11-25/changelog)
4. **Human gates where GitHub learned to put them**: `pr_merge` is elicitation-only; CI with secrets does not run on agent-opened PRs until a writer approves (the `GITHUB_TOKEN` no-recursion rule, generalized). [docs](https://docs.github.com/en/actions/concepts/security/github_token)
5. **Agents never see secrets.** Artifacts tokens, Access service tokens and preview bypass credentials live in Workers and are injected server-side (`preview_fetch`, git proxy), the Nango/Sandbox-1.0 pattern; nothing writes credentials into the sandbox filesystem, so Comment-and-Control style theft has nothing to steal. [Nango](https://nango.dev/blog/how-to-give-ai-agents-access-to-user-accounts-without-exposing-oauth-tokens/)
6. **Egress control** on task sandboxes (allowlist of package registries + beanstalk), as Copilot's firewall does; Sandbox network rules enforce it. [docs](https://developers.cloudflare.com/sandbox/network/)
7. **MCP hygiene**: audience-bound tokens, no passthrough, 403 on bad Origin, random session ids keyed `<user_id>:<session_id>`, scope minimization with incremental consent, `/readonly` endpoint as the default install link. [best practices](https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices)
8. **Attribution and forensics**: commit trailers + `audit_list` + `Agent-Logs-Url` so any incident resolves to client/instance/task/token in one query.
9. **Budgets as a brake**: per-instance write budgets (80/min) and anomaly flags (many-repo reads followed by external writes) throttle a hijacked agent mid-exfiltration.

## 6. UNVERIFIED / open

- Contest judging weights (from sxz.io, not the rules PDF). - Cursor Origin lacking MCP (one source). - Service Auth on `preview_worker` Access apps. - E2B secure-URL header name. - Workers Builds/CI SDK emitting OIDC identity. - D1 export/import clone latency at 500 previews. - Tool annotation defaults (`destructiveHint` true, `openWorldHint` true, others false) are from the schema, not re-fetched here.
