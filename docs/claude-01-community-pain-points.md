## 1. AI PR floods on open source

- curl ended its bug bounty after AI slop reached ~20% of security submissions. "There is no longer a curl bug-bounty program. It officially stops on January 31, 2026." Daniel Stenberg, 2026-01-26, https://daniel.haxx.se/blog/2026/01/26/the-end-of-the-curl-bug-bounty/. Earlier: "we have recently not only received more AI slop but also more human slop." https://daniel.haxx.se/blog/2025/07/14/death-by-a-thousand-slops/ (HN 259 pts / 137 c, https://news.ycombinator.com/item?id=44558665).
- Mitchell Hashimoto's Ghostty policy, since copied verbatim by NetExec and others: "The rise of agentic programming has eliminated the natural effort-based backpressure that previously limited low-effort contributions." https://github.com/ghostty-org/ghostty/pull/10412, 2026-01-22 (HN 502 / 273, https://news.ycombinator.com/item?id=46730504). Commenter Version467: "The biggest surprise... is how little shame people apparently have."
- Godot, Rémi Verschelde (Bluesky, Feb 2026): "AI slop PRs are becoming increasingly draining and demoralizing for Godot maintainers"; the team is "having to second-guess every PR from new contributors, multiple times per day." His only fix: "more funding so we can pay more maintainers to deal with the slop." https://www.pcgamesn.com/ai/godot-ai-generated-submissions
- tldraw auto-closes every external PR (Steve Ruiz, 2026-01-15) "until GitHub provides better technical controls over who can contribute, when, and where." https://www.gigazine.net/gsc_news/en/20260124-tldraw-pause-ext-contrib. Ladybird and openai/codex did the same (codenote.net, secondary).
- ITK Discourse, Niels Dekker, 2026-03-09: "The current stream of AI generated pull requests is a bit overwhelming to me. It is hard for me to review them carefully... AI can produce an enormous amount of pull requests in no time, changing thousands of lines of code." https://discourse.itk.org/t/ai-generated-pull-requests-overwhelming-hard-to-review-carefully/7728
- Hard bans are spreading: pytest, "purely agentic (unsupervised AI) contributions will result in a ban" (https://github.com/pytest-dev/pytest/pull/14223, 2026-02-21); Idris2 "Reject by default non-human contributions" (https://github.com/idris-lang/Idris2/pull/3755, 2026-03-18); YosysHQ "Please do not file pull requests... containing LLM generated code" (https://yosyshq.discourse.group/t/interim-llm-policy/163, 2026-08-31); Rust RFC 3950 (2026-04-17); QEMU (2025-06); Gentoo cited "continuous efforts to force Copilot usage for our repositories" as a reason to leave (devclass, 2026-02-19).
- Volume: pydantic-ai received 136 PRs in 15 days, closed 97; "multiple junk PRs targeting the same bug were submitted within minutes of an issue" *(secondary, dev.to 2026-03-20)*. GitHub's answer on 2026-06-17 was a per-user cap on open PRs for non-write users, https://github.blog/changelog/2026-06-17-limit-open-pull-requests-for-users-without-write-access/. A maintainer in the GitHub discussion: "1 out of 10 PRs created with AI is legitimate and meets the standards required to open that PR."
- The etiquette fight, HN 2026-09-24 (flagged, 15 / 21), rwiggins: "the asymmetry of 'I did very little work here, but I'd like you to spend your time carefully reviewing it nonetheless' can be very annoying." https://news.ycombinator.com/item?id=49824957. Lobsters, bmo (23 upvotes): "the 'contributor' is likely to be a bot with little to no human involvement." https://lobste.rs/s/ax914v/protecting_our_floss_commons_from_llms
- Uncertain: Jazzband's sunset (HN 159 / 59, 2026-03-14) is widely cited as "AI spam"; the HN thread attributes it mainly to a bus factor of one. Treat the AI framing as secondary.

- ITK, Niels Dekker, 2026-03-21: "Cognitive debt accumulates when AI writes code that humans lose shared understanding of." (thread above)
- Steve Klabnik on "What Comes After Git" (HN 77 / 31, 2026-09-11): "You can get claude to produce small, focused stacks, rather than 10,000 line monstrosities." https://news.ycombinator.com/item?id=49652985

## 3. Merge conflicts between parallel agents; intent conflicts; locking hacks

- Foremerge, Show HN 2026-09-21 (42 pts / ~20 c, id 49789356). naw103: "one agent replaces a class while another one is in the process of extending it. Git only notices if the resulting patches happen to touch the same lines." wilsprouse: "Current version control mechanisms are meant for humans, not agents." Dissent, SrslyJosh: "You've got a completely fucked up workflow and instead of fixing the workflow, you're going to bolt something else onto it." https://news.ycombinator.com/item?id=49789356
- GPTree's own account of that failure: "Different worktrees. Different files. Zero textual conflict. Git merged both branches cleanly, and the second change now depended on an extension point the first had deleted... Git compares diffs. It cannot compare plans." https://dev.to/naw103/parallel-coding-agents-without-the-carnage-gf9 (2026-08-27)
- Silent overwrite in a shared checkout: "Two of the agents had been editing auth.js at the same time... Two hours of work from agent one — gone. No warning, no conflict marker, nothing." https://dev.to/switchmandev/how-to-run-5-claude-code-agents-in-parallel-without-them-overwriting-each-other-1dkb (2026-03-10). yureki_lab: "two agents 'fixed' the same bug in opposite directions." https://dev.to/yureki_lab/how-i-run-multiple-claude-code-agents-in-parallel-without-collisions-3pbk (2026-07-11)
- tptacek (HN, 2025-09-03): "the PRs will step on each other, and... I would rather rewrite an entire project than try to pick through a complicated merge conflict." https://news.ycombinator.com/item?id=45110721
- File-locking is now a cottage industry: claude-coord (locks for "migrations, schemas, and shared config"), agenthub ("Soft Locking Protocol based on Intents"), graft ("mutexes, event buses, semaphores, barriers... Conflicts surface at write time, not at merge time"), claude-session-guard, Authora: "Git catches conflicts after they happen... What you need is prevention, not detection." https://dev.to/authora/stop-your-ai-coding-agents-from-fighting-file-level-locking-for-shared-codebases-3pej (2026-03-28)
- jlokier on GitButler's "what comes after Git" (HN 337 / 755, 2026-04-10): "git doesn't support concurrency. Even if you use worktrees, git has a global lock for repo interaction." https://news.ycombinator.com/item?id=47712656
- "Politeness is not a mechanism, so it doesn't survive." Alkis Yuv on agents ignoring each other's status-file claims under context pressure, https://dev.to/alkisyuv/my-agents-kept-overwriting-each-other-so-i-gave-them-claims-2h8k (2026-08-23)

## 4. Merge queues

- GitHub's merge queue silently reverted code for ~3.5h on 2026-04-23 (HN 121 / 45). MarkMarine: "4 people spent hours putting our repo back together at my company after this... now they are breaking the core tenant of what I expect from this service." EdwardDiego: "how do you break one of the most fundamental bits of your system? Time to look at alternatives..." https://news.ycombinator.com/item?id=47881672; GitHub counted 2,092 PRs / 230 repos, later 2,804 (https://www.githubstatus.com/incidents/zsg1lk7w13cf). Blog: "The PR UI lied. You reviewed +29/-34. The commit that landed was +245/-1,137." https://dev.to/varshithvhegde/github-broke-git-the-merge-queue-bug-that-silently-deleted-your-code-4f7i
- Flaky tests stall queues: microsoft/agent-framework, "73% failure rate (22 failures out of 30 runs)... across 7 different PRs regardless of the PR code changes." https://github.com/microsoft/agent-framework/issues/4971 (2026-03-30). dotCMS: "Frontend developers making quick, small PRs wait 45+ minutes in merge queue for full integration/postman tests that cannot possibly be affected by their changes." https://github.com/dotCMS/core/issues/34645 (2026-02-13)
- One YAML line serializes everything: twentyhq's concurrency group on `merge_group.base_ref` "resolves to refs/heads/main for every PR, causing all merge queue entries to serialize behind a single concurrency slot." https://github.com/twentyhq/twenty/pull/18756 (2026-03-19)
- Agents need their own queues: Show HN local merge queue for Claude agents (42 / 22, 2026-07-30): "I have been pushing up to 90 commits a day on a MacBook Air via 4-5 parallel agents." https://news.ycombinator.com/item?id=49104747. On Uber's SubmitQueue (69 / 61), sdfhbdf: "GitHub merge queues just do it in the order you click." https://news.ycombinator.com/item?id=49138084
- The wished-for design (CuriouslyC, HN 2025-09-03): "a massive merge queue with bisection... when a merge batch fails you find the bad patch set in O(log(n)) time and dispatch to an agent for reconciliation."
