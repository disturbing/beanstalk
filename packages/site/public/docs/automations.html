Automations coming soon

An automation is a workflow file in .beanstalk/automations/: the same syntax as GitHub Actions, plus Beanstalk events, built-in actions and a fast isolate runtime. Designed; not built yet.

Files, not database rows

The definitions live in git. When the stalk moves, Beanstalk reads the automation files at the new head and rebuilds its index of schedules and subscriptions. Editing an automation in the web app makes a commit authored by you, which goes through the pre-land check like any bean and takes effect when it reaches the stalk. Automation files are protected paths.

An example

# .beanstalk/automations/posthog-errors.yml
name: PostHog errors → beans
on:
  schedule: [{ cron: "0 * * * *" }]
  validation_red:                     # a Beanstalk event
permissions:
  beans: write
jobs:
  triage:
    runs-on: beanstalk-isolate        # a Dynamic Worker, not a container
    steps:
      - uses: beanstalk/agent@v1
        with:
          harness: claude-code
          budget-usd: 0.50
          mcp: [posthog]
          outputs: open-bean, comment
          prompt: Open one bean per real bug with five or more occurrences in 24 h.

What is added to the GitHub syntax

  • Beanstalk events in on:: bean_opened, bean_landed, bean_red, bean_parked, stalk_moved, validation_red, decision_opened, decision_decided, plus repository_dispatch from a webhook.
  • Built-in actions with typed outputs: open a bean, comment, answer a thread, raise a decision card, notify, or hand a step to an agent session with a budget and a tool allowlist.
  • runs-on: beanstalk-isolate: the job runs in a Dynamic Worker, a V8 isolate loaded at run time. It starts in milliseconds and costs roughly a hundredth to a thousandth of a container job; an hourly automation comes to about $0.06 a month. It has no network by default, gets secrets only as placeholders the platform fills in on allowed hosts, and cannot run shell or native tools, which still need a container.

An automation acts as the repository's own bot, capped by its permissions:, and never lands anything itself: a bean it opens goes through the same checks.
